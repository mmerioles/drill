# tetodoro for android

The android app: Kotlin and Jetpack Compose, no other libraries. It is the
same app as the mac and web ones: the timer engine, the year heatmap, inspo
and account sync are ports of `web/static` (and so of TetodoroCore), and it
speaks the [sync contract](../docs/SYNC.md) like any other device.

- `core/` has the engine, heatmap, sessions and inspo, with no android in it,
  covered by the tests in `app/src/test`.
- `data/` has sessions in SQLite, the sync client and the update check.
- `timer/` has the phone side: an exact alarm for the end of each phase, and
  notifications for the countdown and the end.
- `ui/` has the screens, drawn in the ink look (`ink/`).

`core/InspoVideos.kt` is generated by `scripts/make-inspo.sh`.

## build

Needs JDK 17 and the Android SDK (Android Studio has both).

```sh
cd android
./gradlew test assembleDebug   # app/build/outputs/apk/debug/app-debug.apk
```

## releases

The release workflow builds `tetodoro_<version>.apk` next to the dmg on every
release, with the same version, and `versionCode` set to the run number so
it only goes up. Phones only accept an update signed with the same key as
the app they have, so every release is signed with one key, kept in four
repo secrets:

| secret | value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | the keystore, base64 |
| `ANDROID_KEYSTORE_PASSWORD` | its password |
| `ANDROID_KEY_ALIAS` | `tetodoro` |
| `ANDROID_KEY_PASSWORD` | the key's password |

With the [GitHub CLI](https://cli.github.com), from a keystore and an env file
holding the other three:

```sh
base64 -i android-release.jks | gh secret set ANDROID_KEYSTORE_BASE64
gh secret set -f android-release.env
```

Keep a backup of the keystore. If it's lost, the next apk can't update the
installed one, and everyone has to uninstall and reinstall.

To sign a local release build the same way, export `ANDROID_KEYSTORE_PATH`
and the three other variables before `./gradlew assembleRelease`. Without
them, release builds use the debug key.
